# 统一保存内容与提醒、到期声音状态

[阶段 1 导航](README.md) · [启动方式（CMD）](mvp.md#现在怎么启动cmd) · [提醒设置与素材限制](reminder-settings.md)

## 页面操作

新建和编辑使用同一个“保存”：标题、正文和一次性提醒一起提交，不再先保存正文再设置时间。
时间输入在新建时即可使用，填写时间自动勾选“启用一次性提醒”；单独勾选时默认填入约一分钟后。
取消勾选后保存，会取消尚未执行的提醒；已生成的站内通知不会撤回。
只有改期或重新启用提醒才产生新批次；只改正文不会让已触发提醒再次响铃。
完成/恢复未完成和删除仍是底栏的独立操作，完成前要先保存当前草稿。

标题/正文/提醒时间校验失败或数据库操作失败，数据库整个保存回滚，页面保留草稿供修正重试。
轮询发现提醒已触发，不覆盖正在修改的时间；仅修改时间也纳入关闭/Esc 的未保存确认。
保存已成功而列表刷新失败时，页面明确提示已经保存，避免用户误以为回滚而重复新建。
后端版本不支持新接口时停止提交并提示重启，不回退为两次独立写入。

铃声、音量、样式与导入副本仍沿用账号在当前浏览器共用、修改即保存的规则。
它们不是单条备忘录数据库字段，也不参加这次数据库事务；导入限制与错误保留不变。
没有增加表、自动迁移、上传接口或新依赖。

## 后端事务入口

| 接口 | 成功响应 | 用途 |
| --- | --- | --- |
| `POST /api/notes/save` | 201，`{note, reminder}` | 创建内容及可选提醒。 |
| `PUT /api/notes/{id}/save` | 200，`{note, reminder}` | 修改本人内容及提醒。 |

请求包含 `title`、`content`、`reminderAction`，以及仅 SET 时提供的 `dueAt`：

| reminderAction | 规则 |
| --- | --- |
| KEEP | 不写提醒，保留状态、时间和 generation；不附带 dueAt。 |
| SET | dueAt 为带时区 ISO 时间，未来一年内；使用现有设置/改期校验，递增 generation。已完成记录返回 409。 |
| CANCEL | 只取消待执行提醒；不存在或已经 FIRED 为无操作，不撤回通知；不附带 dueAt。 |

已有单项创建/编辑/提醒 API 保留供教学和兼容；其中 DELETE 提醒对已触发返回 409 的旧约定不变。
新 CANCEL 的含义是确保没有待执行任务，不是声称撤回已经送出的提醒。

`NoteSaveService.save` 是外层事务，复用原 JDBC 服务。编辑先锁本人备忘录，再处理提醒，
与调度/完成的锁顺序一致；新建插入与提醒写入也属于同一个事务。任一写入或最终读取失败整体回滚。
归属只取已验证的 Session 用户，外部不能指定 userId，缺失和他人记录统一 404，写请求保留 CSRF。
没有新增幂等键或乐观锁：响应丢失后盲目重试 POST 仍可能新建重复记录，事务不解决并发编辑覆盖。

## 为什么试听有声，但到期可能没有声

这次不提高默认音量，而是补齐播放路径和可见诊断：

- 试听不自动打开全局到期声音开关。开关关闭时，即使试听成功，到期仍不播放，现在会明确说明原因。
- 保存开启偏好不等于本页播放器已激活；刷新、浏览器暂停、重新加载导入铃声后可能需要用户手势恢复。
- 用户已开启提示音时，点击“保存”会在等待网络请求之前尝试恢复播放器；不会替用户打开关闭的开关。
- 主页和编辑均显示状态，区分开关关闭、音量 0、尚未激活、播放被阻止及已经请求播放。
- 编辑内可点击“恢复到期声音”；音频上下文暂停时立即更新状态。旧播放的迟到失败不覆盖新的恢复结果。

首次加载的历史未读只显示，不补响；激活后新发现的到期通知使用选定铃声，同一通知不重复播放。
播放 Promise 成功、音频上下文运行或页面显示“已请求播放”都不证明扬声器实际出声。
浏览器需要用户手势并可能限制自动播放，见 [Chrome 自动播放策略](https://developer.chrome.com/blog/autoplay/)。
用户这次反馈的具体原因尚未在其浏览器重现，不能将可能的状态条件当作已确认的唯一根因。
关闭网页、休眠、锁屏实时推送仍未实现，页面要保持打开，后端要运行。
用户最初只确认重启后通知仍在；2026-10-08 又确认停机跨到期后重启可见补生成通知。
两项均记录为用户本机反馈，不扩大为关页推送、手机收到或多实例故障恢复已验收。

## 网页验收

下面保留为回归清单，无需重复要求用户手动重测；各浏览器/手机兼容性并未全面覆盖。

1. 重启最新后端，Ctrl+F5 刷新并重新登录；在齿轮开启“到期时播放提示音”。
2. 直接新建一条测试备忘录，在第一次保存前填写约一分钟后的提醒时间，然后仅点击一次“保存”。
   应同时显示内容已保存与“待提醒”；查看声音状态，未激活时点“恢复到期声音”。
3. 关闭编辑但保留网页，等待新提醒；确认选定铃声、大弹层/卡片。后端约 5 秒扫描、前端约 10 秒补查，存在延迟。
   若卡片到达却没声音，请记录主页的声音状态文字，分别检查内置和导入铃声，不用修改浏览器安全策略。
4. 修改同一记录的正文和时间，一次保存；取消勾选再保存应取消待执行任务。只修改正文不得重新触发旧提醒。
5. 输入过去时间再保存，应提示并保留草稿；关闭声音开关，试听仍可响，但实际到期不响且状态说明开关关闭。

只使用专门新建的测试记录，不删除原学习数据；无需重建表或逐个调用接口。

## 提醒规则

- 每条备忘录保留一行提醒事实，设置/改期递增批次 generation，状态为 SCHEDULED/FIRED/CANCELLED。
- 输入带时区的 ISO 时间；页面将本机时间转换为 UTC。只能设置未来一年内的提醒。
- 单实例每隔数秒扫描有限批次的到期任务；停机期间不能及时提醒，启动后补处理未取消的过期任务。
- FIRED 只代表站内通知已入库，不代表手机收到或用户读到。已读是单独状态。
- 设置、完成、取消和调度统一先锁备忘录，再处理提醒，避免完成/改期与调度交叉覆盖。
- 通知入库与提醒标记 FIRED 在同一事务；每个提醒批次最多一条站内通知。
- 完成取消尚未触发的提醒；恢复未完成不会自动恢复旧提醒，需要重新设置。
- 已生成的通知不会因完成而撤回；已触发提醒不能假装取消成功，可再设置一个新批次。
- 删除在同一事务保存回收站快照、移除本人记录及其提醒/通知；最近 30 条可恢复，超出淘汰最早的副本。
- 恢复保留内容与完成状态，生成新 ID，旧提醒/通知不恢复，需要重新设置。

该闭环只建立本地单实例正确性基线，不宣称高并发容量或外部通知的 exactly-once。
提醒集中到期、版本冲突、多实例、重试与真实推送在后续阶段分别实验。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /api/notes/save | 统一新建内容与可选提醒，成功 201，返回 note/reminder。 |
| PUT | /api/notes/{id}/save | 统一编辑内容与保留/设置/取消提醒，成功 200；失败整体回滚。 |
| DELETE | /api/notes/{id} | 删除本人记录，成功 204，不可访问统一 404。 |
| GET | /api/notes/{id}/reminder | 查询本人提醒，无提醒或不可访问返回 404。 |
| PUT | /api/notes/{id}/reminder | 设置或改期，JSON 只有 dueAt，成功 200。 |
| DELETE | /api/notes/{id}/reminder | 取消待执行提醒，成功 204；已触发 409。 |
| GET | /api/notifications?page=0&size=20 | 本人通知分页，不返回备忘录正文；可加 unreadOnly=true 只查未读。 |
| PATCH | /api/notifications/{id}/read | 标记本人通知已读，成功 204，可重复。 |

全部写操作保留 CSRF，归属只来自会话。不能设置已完成记录的提醒（409）。
页面用 textContent 渲染用户文字，不使用用户内容拼接 HTML；不将密码、会话、CSRF 存入 localStorage。

## 统一验收目标

通过浏览器注册/登录，创建和编辑备忘录，设置约一分钟后的提醒，观察站内通知，标记已读，
完成/恢复并检查提醒取消；创建专用临时记录测试删除，退出再登录确认数据仍在。
私密窗口用另一账号检查数据隔离；既有学习账号与记录不用于自动删除测试。

## 现在怎么启动（CMD）

Docker Desktop 保持开启；旧应用若还在运行，在它的启动窗口按 Ctrl+C。只启动一份应用：

```cmd
cd /d D:\1A-project\collab-notes-platform
docker compose up -d --pull never mysql
for /f "usebackq tokens=1,* delims==" %A in (".env") do @set "%A=%B"
mvn --offline spring-boot:run -Dspring-boot.run.arguments=--debug=false
```

让这个 CMD 窗口保持运行，浏览器打开 [本地拾记页面](http://localhost:8080/)。
不需要 npm、不需要前端开发服务器、不需要再复制 Cookie/CSRF token。
已有账号直接登录，重启应用后重新登录；注册成功不会自动登录。
页面会替你获取 CSRF，登录成功后每次写请求使用当前会话的 token。

### 网页验收清单

1. 登录已有账号，确认原有记录仍在；主页只展示列表，点击记录/新建才打开编辑弹窗，未完成优先。
2. 新建一条“MVP 验收专用”备忘录，输入中文、换行与 emoji，在首次保存前直接填写约一分钟后的提醒。
3. 时间按当前设备时区输入，点击一次“保存”，同时保存内容和提醒，显示“待提醒”；按统一保存文档确认声音已激活。
4. 保持页面打开，等待顶部常驻卡片和站内通知出现，核对标题和计划时间，点“标为已读”。
   后端 5 秒扫描一次，前端 10 秒检查一次，会有轮询延迟；不是精确到秒的系统推送。
5. 在同一备忘录再次设置未来提醒，随后“标记完成”，确认提醒显示取消；恢复未完成，旧提醒不能自动恢复。
6. 再填写未来时间并保存；取消勾选“启用一次性提醒”再保存，检查取消状态；可勾选后重新设置/改期。
7. 对这条专用测试记录点“删除”，确认说明移入最近 30 条回收站；列表、提醒与相关通知一起移除。
   打开回收站预览并恢复，确认内容仍在，但旧提醒/通知没有自动恢复。
   不要拿原有重要记录做删除验收。
8. 退出后应回到登录页；重新登录数据仍在。可在私密窗口注册一个测试账号，确认不能看到第一账号的数据。
9. 缩窄浏览器窗口检查单列布局；这不替代手机真机联调。

有未保存文字或提醒时间时切换记录/退出会提示；改变完成状态前要求先保存内容和提醒。
设置提醒不再要求先保存正文；只改正文不重排已触发任务，正文与提醒失败时一起回滚。
页面不会后台自动覆盖你正在编辑的文字；其他设备改动后手动“刷新”获取最新版本。
若会话过期，页面清空当前私密列表和输入区并要求重新登录；不要关闭 CSRF 来解决错误。

## 表与实现说明

`003_create_reminders.sql` 已在本机 collab_notes 执行，创建 reminders 与 notifications；
原 users/notes 结构、账号、记录与数据卷保留。本机不要重复执行建表脚本。
新开发者先按注册/备忘录文档建立 users/notes，再确认两张新表均不存在，才从根目录执行：

```cmd
docker compose exec -T mysql sh -c "MYSQL_PWD=$MYSQL_PASSWORD exec mysql --user=$MYSQL_USER --database=$MYSQL_DATABASE" < src\main\resources\db\manual\003_create_reminders.sql
```

命令内部是容器的 sh，用户终端仍为 CMD；凭据读取容器环境，不在命令行打印。
若已有其中一张表，停止并核验结构，不删表、不重建数据卷，也不要盲目整段重跑。
这些脚本不会随应用启动自动执行。

- `reminder/`：输入校验、归属检查、提醒持久化、事务调度、通知分页与已读。
- `NoteService`：删除与外键级联，完成与取消待执行提醒在同一事务中。
- `NoteTrashRepository` 与 `004_create_note_trash.sql`：删除快照、30 条容量、本人恢复；脚本仅手动执行，本机无需重跑。
- `static/index.html`、`styles.css`、`app.js`：同源界面、状态展示、Session/CSRF 与轮询。
- 安全配置仅放行指定页面资源，API 仍需认证；CSP 限制同源脚本，用户文字通过 textContent 展示。

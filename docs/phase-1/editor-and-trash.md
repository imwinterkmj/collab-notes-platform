# 主页列表、编辑弹窗与最近 30 条回收站

[阶段 1 导航](README.md) · [启动方式（CMD）](mvp.md#现在怎么启动cmd) · [提醒设置](reminder-settings.md)

## 现在的界面

- 设置和退出登录在同一个居中对齐的按钮行，使用一致的高度，不再按文字/SVG 的基线错位。
- 主页“最近更新”改为“备忘录”，只展示列表与通知，不铺开编辑表单。
- 点击备忘录或“新建备忘录”打开独立编辑弹窗，主体包含标题、正文、状态/时间、一次性提醒，以及样式/插画/铃声/音量和导入选项。
- 底栏只有一个“保存”、标记完成/恢复未完成与删除；内容和提醒统一保存，长正文在主体滚动。
- 关闭/Esc 遇到未保存的标题/正文/提醒时间会确认，取消关闭保留草稿；删除确认明确只保存已提交的内容。
- 编辑或回收站打开时不抢弹大提醒，关闭后再显示待处理大提醒；声音与未读补查沿用原逻辑。
- 预览叠在编辑之上，关闭后回到原草稿；导入失败或取消选文件不退出编辑，错误显示在对应导入处。
- 主页“回收站”打开删除记录列表，点击可预览正文，选中后恢复并打开编辑弹窗。

新建时就能填写提醒时间，一次“保存”在同一后端事务提交标题/正文和提醒。
取消勾选后保存可取消待执行任务，具体接口、回滚与声音诊断见 [统一保存](unified-save.md)；密码、Session 与 CSRF 保留。
提醒样式/素材入口的最新调整见 [提醒设置](reminder-settings.md)：当前仍是账号在此浏览器共用一套偏好，不是每条备忘录独立配置。

## 列表排序

服务端整份列表按以下顺序分页，不只排序当前浏览器的一页：

```sql
ORDER BY is_completed ASC, updated_at DESC, id DESC
```

未完成始终在已完成前面；同状态先显示更新较新的记录，同一更新时间按 ID 倒序确定先后。
原有 page/size/hasNext、用户归属和不返回正文的摘要接口保持不变。
原索引不完全覆盖新增的完成状态优先排序；本次没有做性能优化、索引收益或高并发声明，后续用数据测量。
OFFSET 翻页期间完成状态/更新时间变化仍可能造成重复或遗漏，不提供跨请求快照。

## 回收站规则

保留的是**每个账号最近删除的 30 条**，不是 30 天，也不是所有账号共用 30 条。
第 31 条进入时，最早的一条永久移出，无法通过应用恢复；界面删除前和回收站内均提示这一边界。
旧版本已永久删除的记录没有快照，不能找回。

保存标题、正文、完成状态、原创建/更新时间和删除时间，不保存登录信息。
删除后备忘录从正常列表移除，提醒与站内通知通过现有外键级联清理；回收站内的记录不会参与调度。
恢复会生成新的备忘录 ID，保留内容、完成状态和创建时间，更新时间改为恢复时间，并移除回收站副本。
**旧提醒与通知不恢复**，避免过期任务或旧通知突然回来；需要提醒时重新设置。
本步不提供清空回收站、单条永久删除或时间自动过期功能。

实现采用独立 `note_trash` 快照表，不给原 notes 增加软删除字段，避免每条提醒/详情 SQL 忘记过滤回收站。
删除事务先锁当前用户行，再锁本人备忘录：保存快照 → 删除原记录及关联数据 → 清理溢出副本。
恢复也先锁当前用户行，在一个事务内完成新记录插入与副本移除；并发双恢复只有一份记录能恢复成功。
用户行锁用于串行维护该账号的上限，不是把所有账号放进一个全局锁，也不证明高并发容量。
任何中途故障整体回滚，不能出现正文丢失或恢复两份；SQL 都限定会话中的账号。

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| DELETE | `/api/notes/{id}` | 移入回收站，成功 204；不存在/他人记录统一 404。 |
| GET | `/api/notes/trash` | `{items, limit:30}`，最多 30 份本人快照，按删除时间/ID 倒序。 |
| POST | `/api/notes/trash/{id}/restore` | 200 与恢复后的备忘录；不存在/他人副本/已经恢复统一 404，保留 CSRF。 |

回收站有上限且仅在主动打开时读取正文；这些内容不存浏览器持久化，不打印到日志，响应对象 toString 脱敏。

## 数据库与版本切换

本机已手动执行并核验 `src/main/resources/db/manual/004_create_note_trash.sql`，只新增回收站表，
没有改旧表、账号、备忘录或数据卷；不要重跑。脚本不会随应用启动自动执行。

新机器在确认 users/notes/reminders/notifications 已建、note_trash 不存在后，才从仓库根目录手动执行：

```cmd
docker compose exec -T mysql sh -c "MYSQL_PWD=$MYSQL_PASSWORD exec mysql --user=$MYSQL_USER --database=$MYSQL_DATABASE --default-character-set=utf8mb4" < src\main\resources\db\manual\004_create_note_trash.sql
```

外层终端是 CMD，内部是容器 sh；密码读取容器环境，不打印。表已存在就停止核验，不删表重建。

验收前必须重启 Spring Boot，不能仅刷新静态页面。新页面会在删除前确认回收站接口存在，
旧后端不支持时阻止 DELETE 并提示重启，避免把旧永久删除行为误称为可恢复。

## 手动验收

1. 旧应用的启动窗口 Ctrl+C，然后按上面的启动链接重新运行；浏览器 Ctrl+F5，重新登录。
2. 确认设置/退出按钮同高同线，主页没有编辑区，“最近更新”已改为“备忘录”。
3. 新建两条专用测试备忘录，标记其中较新的一条完成，确认未完成仍排在前面；重新恢复未完成后按更新顺序排列。
4. 点击记录打开弹窗，检查标题、正文和提醒；缩窄窗口/滚动长正文，底部操作按钮仍可用。
5. 修改标题不保存，关闭/Esc 选择取消，草稿应保留；再保存，确认反馈在弹窗内。
6. 给测试记录设未来提醒，再删除，确认已移到回收站且列表/关联提醒/通知移除。
7. 打开回收站预览并恢复，内容、完成状态、创建时间保留，旧提醒不存在；需要提醒时重新设置。
8. 私密窗口用另一账号看不到该副本。30 条上限及并发/回滚由自动测试覆盖，不要求手动删除 31 条学习记录。

只使用新建测试记录做删除验收，保留原有账号与重要备忘录。

# 主动提醒：页面卡片、提示音与电脑桌面通知

[阶段 1 导航](README.md) · [MVP 启动方式](mvp.md#现在怎么启动cmd)

本步补齐“提醒发生后，用户能注意到”的体验，不再只依赖站内通知列表或短暂浮层。
不新增下载、表、推送服务器或中间件；使用原生 Web Audio 与 Notifications API。
代码已实现，用户反馈基础体验基本没问题；不推断已覆盖所有系统/手机表现。
全局声音/桌面开关在右上角齿轮，样式、铃声、图片/铃声导入与试听在备忘录编辑弹窗，见 [提醒设置](reminder-settings.md)。

## 现在有什么

- 顶部常驻待处理卡片、未读数与浏览器标题提示；卡片不会按秒自动消失。
- 查看备忘录不会自动标记已读；有未保存文字时，先确认是否放弃编辑。
- “收起卡片”只影响本页展示，不写数据库、不标记已读；可点“显示收起的卡片”恢复。
- “标为已读”写入服务端，下轮检查其他设备也能获取该状态；相关系统提醒尝试关闭。
- 提示音由点击开启，提供测试按钮与关闭开关；一次检查发现多条提醒，只播放一组短音，不循环响铃。
- 桌面通知由点击申请权限；明确提示可能显示标题。提供测试与关闭入口，关闭本页开关不撤销站点权限。
- 多条新发现提醒合并为一条桌面提示；点击可回到本页查看首条备忘录，不自动标记已读。
- 权限拒绝、弹窗未授权、不支持、安全上下文不足、声音暂停或展示失败，保留页面卡片并提示回退。
- 每 10 秒尝试检查；切回页面或聚焦窗口立即补查，同一轮询尚未完成时不重叠。
- 不再因为 document.hidden 主动停查，但浏览器仍可能节流、冻结或丢弃后台页面。
- 网络失败保留已加载卡片并提示稍后重试；退出/会话失效清空私密卡片，关闭本页创建的桌面提醒。

开关与非敏感样式偏好现按账号保存在当前浏览器；导入副本存 IndexedDB，不上传。
去重和收起状态仍仅保存在本页内存，按本次登录隔离；不保存密码、Cookie 或 CSRF。
刷新/重新登录后声音可能需要点击“恢复声音”，桌面权限不自动申请。首次检查的历史未读显示卡片，但不突然补响或补弹。
后续新发现的未读 ID 在同一页面、本次登录内只主动提示一次；多个标签页各自工作，
尚未实现标签页间统一响铃协调，也不把这种本页去重叫作设备级或全局 exactly-once。

## 仍不支持什么

网页必须保持打开，且服务端要运行。本步不是 Web Push、PWA 或原生 App，
关闭网页、电脑休眠、浏览器冻结和手机锁屏时没有可靠实时推送。切回后补查不等于准点送达。
桌面权限为 granted 只表示获准尝试展示；勿扰、音量和操作系统设置仍影响是否真的看到或听到。
移动浏览器可能不支持直接创建 Notification，失败时回退；手机系统通知需要另行设计。

浏览器限制依据：[MDN 通知 API 使用说明](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)
与 [Chrome 自动播放策略](https://developer.chrome.com/blog/autoplay/)。

服务端 FIRED＝站内通知入库；浏览器检测到＝前端获取通知；权限已授权、请求展示、
设备实际展示和用户已读仍是不同事实。本步不增加虚假的“推送成功”数据库状态。

## 未读补查与查询边界

增加 `GET /api/notifications?unreadOnly=true&page=0&size=100`。
默认 unreadOnly=false，旧分页接口行为保留；SQL 仍通过会话中的用户 ID 限定归属。
先过滤未读再分页，因此已读历史不会占据首页并遮挡旧未读。无需迁移表结构。

每轮未读补查最多 5 页、500 条，顶部最多 10 张卡片；有更多时显示“500+”及边界提示，
完整历史仍在站内通知分页中。加载满上限不等于获得完整未读总数，不把该数字当作精确统计。
分页会对重复 ID 去重；多页任一失败不提交半份结果，保留上一轮卡片。
OFFSET 翻页期间遇到并发插入/已读/删除仍可能暂时跳项，下一轮重新检查；没有快照保证。
尚未测量通知积压下的查询耗时，未新增性能索引或宣称高并发能力。

## 网页验收（不需要逐接口输入命令）

1. 按 MVP 文档重启应用，打开 `http://localhost:8080/`，按 Ctrl+F5 加载新资源，重新登录。
2. 点击右上角齿轮“设置”，勾选到期声音，必要时点“恢复声音”；关闭设置，打开备忘录编辑弹窗试听铃声，检查实际声音与音量。
3. 在设置勾选桌面通知或点“申请 / 检查权限”，由你自己决定是否允许；允许后点“测试桌面通知”，确认实际看见弹窗。
   拒绝或没有弹窗时，不算桌面验收通过，但页面卡片应继续正常使用。
4. 新建专用测试备忘录，设置约一分钟后提醒。保持页面打开，等待顶部卡片、未读标题、声音/桌面提示。
   后端默认 5 秒扫描、前端 10 秒尝试检查，存在延迟，不按绝对准点验收。
5. 提醒出现后等两个检查周期，应不重复响/弹；收起卡片，未读数不变，再恢复卡片。
6. 点击查看备忘录，仍应未读；点击标为已读，卡片消失，站内通知变已读。
7. 再设一个未来提醒，切到其他窗口但不关闭网页。观察后台提醒，切回后检查卡片；
   浏览器若暂停后台，记录补查延迟，不把冻结期间没提醒误说成已支持后台推送。
8. 关闭声音/桌面开关后再设提醒，顶部卡片仍出现；退出后不残留上一账号的标题或卡片。
9. 关闭网页后到期，再打开登录：看到历史未读卡片、不突然补响。手机锁屏实时通知不属于本次验收。

仅使用新建的测试记录做删除验收，保留学习账号和既有记录。

## 改了哪些代码

- `static/reminder-alerts.js`：主动提醒状态、历史基线、去重、音频生成、授权/展示、降级和退出清理。
- `static/app.js`：常驻卡片、未读补查、后台检查与切回补查；按账号轮次隔离迟到结果，保留 Session/CSRF。
- `static/index.html`、`styles.css`：提醒开关、测试入口、常驻区域与窄屏布局。
- `NotificationController` / `NotificationService`：未读筛选；原已读接口与调度事务逻辑不变。
- `SecurityConfiguration`：只增加新脚本的匿名 GET 白名单，不开放 API；后续导入仅为图片/音频增加本地 Blob 来源，脚本策略不放宽。
- 新增原生 Node 状态与轻量 DOM 替身测试；补充未读筛选、归属、分页、错误脱敏验证。

用户已自行将密码下限改为 1，本步保留 1～128 码点并同步旧测试与说明。
这是本地练习设置，不建议直接用于正式上线；哈希、CSRF 和会话机制保持不变。

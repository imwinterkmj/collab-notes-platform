# 从 localhost 到电脑和手机都能使用

这是一份后续路线，不表示已经部署、购买服务、安装 PWA 或实现关页推送；本次不下载工具、不改防火墙。

## localhost 是什么

`localhost` 表示正在访问网页的这台设备。现在电脑浏览器访问的是电脑本地运行的 Spring Boot。
手机输入同一 localhost 地址访问的是手机自己，不是电脑。网页形态不等于只能 localhost；
应用部署到可访问的服务器后，可用正式 HTTPS 域名访问，电脑和手机连接同一个后端。

## 建议顺序

1. 完成现在的本机网页验收，确定手机是 Android 还是 iPhone，以及具体浏览器。
2. 如需同一 Wi-Fi 真机测试，另行确认范围后按电脑局域网地址和限定防火墙规则联调。
   不关闭防火墙、不开放数据库 3306 到公网；普通局域网 HTTP 不等于安全上下文，通知能力可能不可用。
   当前不安排通过明文局域网传输账号密码，先准备 HTTPS 测试方式与专用测试凭据。
3. 部署常驻后端与数据库，配置域名、HTTPS、同源网页/API、进程启动/重启、日志和备份。
   电脑关机不再影响服务器上的提醒调度。可以先运行 Java 21 + 应用 JAR，不要求先把应用 Docker 化。
4. 再评估 PWA：让适配手机/电脑的网页可安装到主屏幕或桌面，减少手动打开网址。
   安装方式及支持随系统/浏览器而异；PWA 不等于 Android APK 或 iOS 原生应用，
   也不因为有图标就自动获得关页提醒。依据见 [MDN PWA 安装指南](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing)。
5. 独立接入可靠推送：根据目标系统验证 Web Push、Service Worker、设备订阅及权限；
   分开记录渠道接受、设备实际展示和用户已读。若需要更强的系统交互，再评估原生客户端。
   推送受设备/系统限制，不能承诺休眠、断网时绝对准点，见 [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)。

服务器不是多端同步的全部：当前数据库共享读写已存在，但编辑冲突检测、离线同步、标签页统一响铃仍待实现。
Web Push 与缓存/MQ 是不同问题；没有测量依据，不为了部署或 PWA 提前引入 Redis、Kafka 或搜索服务。

## 上线前要补的事

- 本地学习的 1 字符密码下限必须重新评估；补齐登录保护、账号恢复与安全配置验收。
- 使用 HTTPS，检查会话 Cookie 的 Secure 等配置，保留同源与 CSRF，不靠开放 CORS 解决部署。
- 密码、密钥通过运行环境管理，不提交 Git、不写进日志；生产关闭不必要的调试日志。
- 数据库仅在必要的私网/主机网络可达，持久化并验证备份恢复，不公开暴露 3306。
- 手机真机、服务重启、通知权限拒绝和设备离线分别验收，明确无法保证的提醒场景。
- 现有 MySQL 学习数据不会自动迁移到服务器；若需迁移，单独确认范围并先备份。
- 偏好和导入文件目前仅在浏览器来源下保存；从 localhost 换域名后需重新导入，尚无云端素材同步。

正式部署需另行确认服务器、域名、手机系统和下载/费用，再实施。当前不提供未获授权的购买或安装操作。
